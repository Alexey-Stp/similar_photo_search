## SPS-2 — Bootstrap project structure, Clean Architecture modules and DI container

### Description

Create the Xcode project with local Swift Package targets Domain, Data and Presentation, plus the app target as the composition root.
Add a lightweight DI container (`AppContainer`) that builds the concrete services and passes them into view models.
Set up SwiftLint, Swift 6 language mode and a CI workflow (`xcodebuild test`).

### Acceptance Criteria

- Domain has no dependency on Photos, Vision, SwiftData or SwiftUI. CI fails if such an import appears.
- The app target is the only place where concrete implementations are created.
- Strict concurrency is set to complete, and the build has zero warnings.
- The test targets DomainTests and DataTests exist and run in CI.
- Edge case: a build with a missing Info.plist usage key fails a CI lint step.

### Technical Notes

SPM local packages, `@main` App with `AppContainer` injected through `.environment(...)`, `@Observable` view models,
XCTest or Swift Testing (`import Testing`). Use one xcconfig per configuration (Debug/Release).

### AI Implementation Prompt

```
[Shared preamble]
TASK: Generate the skeleton of an iOS 17 SwiftUI app named "SimilarPhotos" using Clean Architecture
with three local Swift packages: Domain, Data, Presentation.
- Domain: entities `PhotoAsset` (id: String, creationDate: Date?, pixelWidth: Int, pixelHeight: Int,
  isFavorite: Bool, mediaSubtypes: Set<PhotoSubtype>), `SimilarityCluster`, and protocols
  `PhotoLibraryRepository`, `FeaturePrintService`, `FeaturePrintCache`, `ClusteringEngine`,
  `QualityScorer`, `AssetDeletionService`. All entities are Sendable structs.
- Data: empty conforming types with `fatalError("Not implemented")` placeholders.
- Presentation: `RootView` that switches on an `AppRoute` enum (onboarding, permissionDenied, home).
- App target: `AppContainer` (final class, @MainActor) that builds concrete services and exposes
  view-model factories; inject via SwiftUI `.environment`.
- Provide Package.swift files with swiftLanguageModes [.v6], a GitHub Actions workflow running
  `xcodebuild test` on an iOS simulator, and a script that fails CI if Domain imports Photos/Vision/SwiftData/SwiftUI.
```

### Risk Assessment

Too many modules early on slows iteration; keep it to three packages.
Swift 6 strict concurrency will flag PhotoKit types (`PHAsset` is not `Sendable`), so pass `localIdentifier` strings across actors instead of `PHAsset` objects.

### Implementation notes

- The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`; `SimilarPhotos.xcodeproj` is git-ignored.
- The Data package's library/module is named `DataLayer` (package and folder stay `Data`) so the module name does not shadow `Foundation.Data`.
- Guard scripts live in `scripts/` and run in the CI `lint` job.

## SPS-7 — Implement `PhotoLibraryRepository` for asset fetching with filters

### Description

Wrap `PHAsset` fetching behind `PhotoLibraryRepository`. Return lightweight `PhotoAsset` domain models,
or an index-based lazy sequence so that 100k objects are not materialized at once.
Support these filters: media type image only, exclude screenshots (optional), exclude hidden, specific album(s), date range.

### Acceptance Criteria

- Fetch uses `PHFetchOptions` with predicate `mediaType == %d` (`PHAssetMediaType.image`) and sort `creationDate` descending.
- The order is a hard contract: assets are delivered strictly by `creationDate` descending (ties broken by `localIdentifier`),
  because session splitting (SPS-26) and live results depend on it.
- Option to exclude screenshots through `!(mediaSubtypes & %d)` with `PHAssetMediaSubtype.photoScreenshot`.
- Hidden assets are excluded (`includeHiddenAssets = false`, the default; assert it in a test).
- Live Photos are included as still images. Bursts: only the representative is fetched by default (`includeAllBurstAssets = false`).
- Album scope: `PHAssetCollection.fetchAssetCollections(with: .album/.smartAlbum, ...)`, then `PHAsset.fetchAssets(in:options:)`.
- Edge case: an empty library returns an empty result and the UI shows the "No photos" state.
- Edge case: assets with `creationDate == nil` sort last and are still processed.
- Edge case: under Limited access, only the accessible assets are returned, and the count matches.
- Performance: enumerating 50k assets into identifiers takes under 2 s on an iPhone 12, measured with `XCTMetric`/`measure`.

### Technical Notes

`PHFetchResult<PHAsset>` is lazy, so iterate by index range (`objects(at: IndexSet)`) instead of `enumerateObjects` over everything when paging.
Map to `PhotoAsset(id: localIdentifier, …)`. The repository is an `actor` or a `Sendable` final class with no mutable state.

### Risk Assessment

Turning the whole `PHFetchResult` into an array at once causes memory spikes and UI hangs.
`PHAsset` is not `Sendable`, so passing it between actors breaks Swift 6 compilation.

### Implementation notes

- API: `assetCount(scope:)`, `assetPages(scope:pageSize:)` and `albums()`. The order contract is `PhotoAsset.libraryOrder` (Domain).
- PhotoKit cannot sort by `localIdentifier`, so `OrderedAssetPager` (Data) restores the contract: the run of photos sharing a
  page's last timestamp is held back to the next page, and each page is sorted. A page can therefore be slightly larger than `pageSize`.
- Photos without a date are collected while paging and delivered after all dated photos, sorted by id.
- Several selected albums are merged by date and de-duplicated by id. `assetCount` for overlapping albums is an upper bound.
- Pages are produced on demand (`AsyncThrowingStream(unfolding:)`), so the stream never runs ahead of its consumer.
- `PhotoAsset` gained `modificationDate` (cache key, SPS-13) and `burstIdentifier` (SPS-16, SPS-26).
- The limited-access banner still uses `PhotoPermissionService.accessiblePhotoCount()`; switching it to the repository count is left to SPS-20.
- The 50k performance test (`PhotoLibraryPerformanceTests`) is device-only: set `RUN_DEVICE_PERFORMANCE_TESTS=1` in the scheme.
